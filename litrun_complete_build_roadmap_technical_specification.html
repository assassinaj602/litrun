Why Litrun Exists

The Embedded AI Problem Nobody Solved

Ollama excels on Apple Silicon and desktop Macs. llama.cpp works if you are an expert willing to compile with arcane flags. HuggingFace assumes infinite cloud GPUs. Every silicon vendor pushes proprietary, closed SDKs. litrun provides the missing neutral, hardware-aware runtime layer.

What Developers Suffer Through Today

  • 01.
    SoC & ISA Fragmentation: Every single board (BCM2711, BCM2712, RK3588, TDA4VM) requires different compile flags, SIMD extensions (NEON, FP16, DotProd, i8mm), and vendor toolchains.
  • 02.
    45-Minute On-Device Compilations: Pi 4 compiling llama.cpp from source is painfully slow, thermal throttles after 10 minutes, and fails whenever memory is exhausted during linking.
  • 03.
    Quantization Guesswork: Developers must guess between Q4_K_M, Q5_K_S, IQ3_XS without knowing whether the KV cache + weights will fit their specific board RAM.
  • 04.
    Disjoint Runtime Abstractions: llama.cpp, ONNX Runtime, and vendor NPU SDKs (like Rockchip RKNN) all share zero API commonality. Code must be rewritten for each chip.
  • 05.
    Silent Device Kernel Panics: Zero safety guardrails. When RAM spikes during long context inference, the Linux OOM-killer randomly terminates services or crashes the board entirely.

How Litrun Resolves It Elegantly

  • 01.
    Universal Hardware Fingerprinter: A lightweight C binary probes /proc/cpuinfo, devicetree model, and auxiliary vectors in <5ms, producing a normalized hardware profile ID.
  • 02.
    Precompiled Multi-SoC Binary Registry: Pre-built, cross-compiled inference binaries for each target SoC are hosted on GitHub Releases and pulled instantly like container layers.
  • 03.
    Hardware-Aware Model Registry: Every curated model entry defines precise memory envelopes. Litrun selects the highest-accuracy quantization that safely fits inside free memory.
  • 04.
    Unified Inference API & Drop-in REST: One unified CLI, Python SDK (from litrun import Model), and OpenAI-compatible HTTP server (/v1/chat/completions).
  • 05.
    Active Resource Governor: Enforces hard RAM ceilings, monitors thermal zones, blocks dangerous allocations, and degrades gracefully to smaller quantized models before swapping.

/* litrun core: hardware fingerprinting on embedded Linux */
#include <stdio.h>
#include <string.h>
#include <sys/auxv.h>
#include <sys/sysinfo.h>

typedef struct {
    char board_name[128];
    char soc[64];
    int  cores;
    long ram_total_mb;
    long ram_avail_mb;
    int  has_neon;
    int  has_dotprod;
    int  has_i8mm;
} litrun_hw_profile_t;

int litrun_probe_hardware(litrun_hw_profile_t *p) {
    struct sysinfo si;
    sysinfo(&si);
    p->ram_total_mb = si.totalram / (1024 * 1024);
    p->ram_avail_mb = si.freeram / (1024 * 1024);

    /* Probe devicetree model (Raspberry Pi, Orange Pi, Rockchip) */
    FILE *f = fopen("/sys/firmware/devicetree/base/model", "r");
    if (f) {
        fgets(p->board_name, sizeof(p->board_name), f);
        fclose(f);
    }

    /* Query ARM64 auxiliary vector hardware capabilities */
#ifdef __aarch64__
    unsigned long hwcap = getauxval(AT_HWCAP);
    p->has_neon = (hwcap & HWCAP_ASIMD) ? 1 : 0;
    p->has_dotprod = (hwcap & HWCAP_ASIMDDP) ? 1 : 0;
#endif
    return 0;
}
